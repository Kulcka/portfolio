# ИИ-консультант по документам компании

Бот отвечает клиентам и сотрудникам по вашим документам — тарифам, регламентам,
FAQ, договорам — и **к каждому ответу прикладывает ссылку на источник**:
файл и страницу (PDF) или раздел (Word, Markdown, текст). Если ответа в
документах нет, бот так и говорит и предлагает связаться с менеджером, а не
выдумывает.

Работает в Telegram и из командной строки. Модель — на выбор: YandexGPT,
GigaChat, OpenAI и совместимые сервисы или **локальная модель на вашем
сервере** (Ollama, vLLM, LM Studio), когда документы не должны покидать
компанию.

```
Вопрос: Можно ли отправить ноутбук с литиевым аккумулятором?

Ответ:  Литиевые аккумуляторы принимаются только установленными в устройство,
        ёмкостью не более 100 Вт·ч. [zapreshchennye-vlozheniya.txt, раздел «ОГРАНИЧЕНО К ПЕРЕСЫЛКЕ»]

Источники:
• [zapreshchennye-vlozheniya.txt, раздел «ОГРАНИЧЕНО К ПЕРЕСЫЛКЕ»]
```

```
Вопрос: Как приготовить борщ?

Ответ:  В документах нет ответа на этот вопрос. Пожалуйста, свяжитесь с менеджером
        по телефону +7 (000) 000-00-00 или support@romashka-logistic.example.
```

Примеры выше — вывод офлайн-режима на демо-документах вымышленной компании
ООО «Ромашка-Логистик» (папка `demo_docs/`, все цены и контакты вымышлены).

## Что умеет

- **Форматы документов:** PDF (с текстовым слоем), DOCX (включая таблицы), TXT
  (UTF-8 и Windows-1251), Markdown. Колонтитулы PDF («Страница 2 из 5», шапка)
  убираются автоматически. Сканы без текста бот честно помечает: нужен OCR.
- **Индекс на диске с частичной пересборкой:** после правки одного файла
  перечитывается только он; удалённые файлы уходят из базы. Команда `/reindex`
  в Telegram обновляет базу без перезапуска бота.
- **Поиск по-русски:** BM25 с нормализацией (регистр, «ё», основы слов
  Snowball, стоп-слова), словарь синонимов («цена» находит «стоимость» и
  «тариф»; свой словарь подключается файлом), учёт неровных форм слова
  («задержали» ↔ «задержка»).
- **Гибридный поиск (по желанию):** эмбеддинги через любой OpenAI-совместимый
  сервис — OpenAI, Yandex, GigaChat, Ollama. Результаты сливаются методом RRF;
  если сервис эмбеддингов недоступен, поиск продолжает работать на BM25.
- **Честные отказы:** если в найденных фрагментах мало слов вопроса, модель
  даже не вызывается — бот сразу отвечает «в документах нет» (и не тратит
  токены). Модель тоже обязана ответить служебным словом, если ответа нет.
- **Ссылки проверяются:** ответ без ссылки на переданный фрагмент пользователю
  не показывается; ссылки на несуществующие документы вырезаются.
- **Защита от промпт-инъекций:** документы и вопрос передаются модели как
  данные в отдельных блоках (закрыть блок изнутри нельзя — скобки
  экранируются); фрагменты с фразами вида «игнорируй инструкции» помечаются;
  вопрос с такими фразами получает отказ без вызова модели; если модель
  выдала служебную метку из системных правил — ответ заменяется отказом.
  В демо-корпусе специально лежит «письмо партнёра» с инъекцией.
- **Секреты не утекают:** ключи и токены маскируются в журнале, в
  трассировках и в текстах ошибок (проверено тестами, в том числе когда
  сервис сам возвращает ключ в тексте ошибки).
- **Telegram-бот (aiogram 3):** ответы со списком источников, защита от
  частых запросов, длинные ответы режутся по лимиту Telegram, команды
  `/reindex` и `/stats` только для администраторов.

## Какие модели поддерживаются

| Провайдер | Как подключается | Проверено |
|---|---|---|
| **Локальные модели** — Ollama, vLLM, LM Studio | OpenAI-совместимый API на вашем сервере; ключ не нужен. **Документы и вопросы не уходят за пределы сервера** | формат запроса — тестами на подменённом HTTP; с живой моделью не запускалось |
| **OpenAI, OpenRouter** и другие совместимые | `LLM_PROVIDER=openai`, адрес и ключ в `.env` | тестами на подменённом HTTP |
| **YandexGPT** (Yandex Cloud AI Studio) | свой адаптер к API генерации текста (`/foundationModels/v1/completion`, ключ `Api-Key`) или OpenAI-совместимый режим (`ai.api.cloud.yandex.net/v1`, в нём же Qwen3 и gpt-oss из каталога Яндекса). По умолчанию шлём `x-data-logging-enabled: false` — по документации Яндекса такие запросы не сохраняются на их серверах | тестами на подменённом HTTP; **живой запрос не делался** (нужен ключ) |
| **GigaChat** (Сбер) | свой адаптер с OAuth: ключ авторизации → токен доступа на 30 минут (кэшируется и обновляется сам, в том числе при ответе 401), затем OpenAI-совместимый `api.giga.chat/v1` | тестами на подменённом HTTP; **живой запрос не делался** (нужен ключ). Проверено, что без сертификата Минцифры TLS к серверам GigaChat не проходит — путь к сертификату задаётся в `GIGACHAT_CA_BUNDLE` |
| **Офлайн-режим** `extractive` | без нейросети и сети: цитирует самые подходящие строки лучшего фрагмента | работает, на нём сняты цифры ниже |

Для российских заказчиков: YandexGPT и GigaChat — отечественные модели, а
локальная модель вообще не передаёт данные третьим лицам. Это упрощает
выполнение требований 152-ФЗ, но итоговую схему обработки персональных
данных стоит согласовать с вашим юристом. Тексты вопросов по умолчанию **не
пишутся** в журнал бота (`LOG_QUESTIONS=false`).

## Качество на демо-корпусе

7 документов (2 PDF, 2 DOCX, 2 TXT, 1 MD), 27 фрагментов. Набор проверки —
`eval/questions.json`: 20 вопросов по теме, сформулированных иначе, чем в
документах, с ожидаемым источником, и 10 вопросов не по теме (включая
коварные: «Сколько стоит доставка пиццы?», попытку инъекции).
Порог отказа подобран на половине вопросов (dev) и проверен на другой
половине (test), чтобы не подгонять его под те же вопросы.

| Метрика | Все вопросы | Только test-часть |
|---|---|---|
| hit@1 — нужный фрагмент первым | 17/20 = 85% | 9/10 = 90% |
| **hit@3** — нужный фрагмент в тройке | **18/20 = 90%** | 10/10 = 100% |
| **Правильные отказы** на вопросы не по теме | **10/10 = 100%** | 5/5 = 100% |
| Ложные отказы на вопросы по теме (контроль) | 2/20 = 10% | 1/10 = 10% |

Промахи честно показаны командой `eval`: «Где посмотреть, где сейчас моя
посылка?» — в вопросе нет ни одного слова из раздела «Как отследить
посылку?»; такие перефразы закрывает гибридный поиск с эмбеддингами.
Отказы сняты в офлайн-режиме; с настоящей моделью добавляется второй слой
отказа (модель отвечает «нет ответа»), его качество зависит от модели и
замеряется той же командой после подключения ключа.

На ваших документах цифры будут другими: порог нужно перемерить на 20–30
ваших типичных вопросах (`python -m docs_assistant eval --tune`).

## Как загрузить свои документы

1. Положите файлы в папку (подпапки можно): PDF, DOCX, TXT, MD.
2. Укажите папку в `.env`: `DOCS_DIR=D:\docs` (или передайте в команде).
3. Постройте индекс: `python -m docs_assistant ingest D:\docs`.
   Команда выведет, сколько файлов прочитано и какие пропущены с причиной.
4. После изменения документов — снова `ingest` или `/reindex` в боте:
   перечитаются только изменённые файлы.

Советы: у PDF должен быть текстовый слой (сканы сначала через OCR); в Word
используйте стили «Заголовок 1/2» — по ним бот делает ссылки на разделы.

## Установка и запуск

Нужен Python 3.10+.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env            # заполните нужные строки
.\.venv\Scripts\python -m docs_assistant ingest demo_docs
.\.venv\Scripts\python -m docs_assistant ask "Сколько стоит доставка посылки до 5 кг?"
.\.venv\Scripts\python -m docs_assistant bot      # Telegram-бот
```

Для постоянной работы на Windows — задача Планировщика с запуском
`.venv\Scripts\pythonw.exe -m docs_assistant bot` при старте системы.

### Linux (systemd)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && chmod 600 .env    # заполните
.venv/bin/python -m docs_assistant ingest /path/to/docs
```

Служба: `deploy/ai-docs-assistant-bot.service` — внутри пошаговая установка
(отдельный пользователь, автоперезапуск, запись только в папку индекса).

### Docker

`Dockerfile` приложен (сборка в этой поставке не проверялась — Docker на
машине разработки не установлен):

```bash
docker build -t ai-docs-assistant .
docker run -d --restart unless-stopped --env-file .env \
  -v "$PWD/docs:/app/docs:ro" -v docs-index:/app/data ai-docs-assistant
```

### Команды

| Команда | Что делает |
|---|---|
| `ingest [папка]` | построить/обновить индекс |
| `ask "вопрос"` | ответ со ссылками; `--json` — для интеграций, `--debug` — найденные фрагменты |
| `search "запрос"` | только поиск, с оценками — удобно настраивать синонимы и порог |
| `eval [--tune]` | метрики качества; `--tune` — подбор порога отказа |
| `bot` | запустить Telegram-бота |

Общие ключи: `--provider openai|yandexgpt|gigachat|extractive`, `--docs`,
`--index`, `--env`.

### Подключение модели (фрагменты `.env`)

```ini
# Локальная модель в Ollama — данные не покидают сервер
LLM_PROVIDER=openai
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_MODEL=qwen2.5:7b

# YandexGPT: API-ключ сервисного аккаунта с ролью ai.languageModels.user
LLM_PROVIDER=yandexgpt
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=b1g...
YANDEX_MODEL=yandexgpt-lite

# GigaChat: ключ авторизации из личного кабинета + сертификат Минцифры
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=...
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca.cer
```

Сертификат Минцифры для GigaChat скачивается на https://www.gosuslugi.ru/crt
(так указано в документации Сбера); проверку сертификата бот не отключает.

## Сколько стоит работа модели

Один вопрос к модели — это системные правила, до 4 найденных фрагментов и сам
вопрос: на демо-корпусе в среднем **около 2 800 символов** (от 2 100 до
3 400), плюс ответ до `LLM_MAX_TOKENS` токенов. Сколько это токенов, зависит
от токенизатора модели; точное число возвращает сама модель (поле `usage`
сохраняется в ответе). Вопросы, на которые ответа в документах нет, модель
не вызывают вовсе и ничего не стоят.

Проверенные цены (на 27.09.2026):

- **GigaChat, юрлица, оплата по факту** (страница тарифов Сбера, редакция от
  16.09.2026, цены с НДС за 1000 токенов, синхронный режим): Lite — 0,065 ₽,
  Pro — 0,5 ₽, Max — 0,65 ₽; эмбеддинги — 0,014 ₽. Минимальный платёж — 600 ₽
  в месяц, если сервисом пользовались. Там же сказано, что с 01.09.2026 новые
  клиенты оплачивают модели на платформе cloud.ru — цены для новых клиентов
  смотрите там (мы их не проверяли).
- **GigaChat, физлица:** бесплатный режим Freemium — по странице тарифов для
  физлиц, пакеты токенов на 12 месяцев (подходит для пилота).
- **YandexGPT, OpenAI, OpenRouter:** цены не проверялись — смотрите
  официальные прайс-листы провайдеров перед запуском.
- **Локальная модель:** оплаты за токены нет, нужен сервер с видеокартой или
  достаточным объёмом памяти под выбранную модель.

## Устройство проекта

```
docs_assistant/
  loaders.py      чтение PDF/DOCX/TXT/MD, разделы и страницы, колонтитулы
  chunking.py     фрагменты с перекрытием, не пересекают границу страницы/раздела
  index.py        индекс на диске, частичная пересборка по хешу файла
  textproc.py     нормализация, стемминг, стоп-слова, синонимы
  bm25.py         BM25 без внешних зависимостей
  retriever.py    поиск, гибрид с эмбеддингами (RRF), решение «есть ли ответ»
  embeddings.py   кэш векторов на диске
  prompt.py       сборка запроса к модели, защита от инъекций
  citations.py    формат ссылок и их проверка в ответе
  assistant.py    сквозной сценарий вопрос → ответ
  llm/            провайдеры: openai_compat, yandexgpt, gigachat, fake/extractive
  telegram_bot.py бот на aiogram 3
  evaluation.py   метрики hit@k и отказов
  security.py     маскировка секретов в журнале и ошибках
demo_docs/        демо-документы (пересборка: scripts/build_demo_corpus.py)
eval/             вопросы для оценки
tests/            73 теста pytest
deploy/           служба systemd
```

Тесты: `pip install -r requirements-dev.txt`, затем `python -m pytest`.
Покрыты загрузка каждого формата, разбивка, частичная переиндексация,
поиск, сборка запроса и защита от инъекций, отказы, формат и проверка
ссылок, сквозной сценарий на фейковой модели, запросы к OpenAI-совместимому
API, YandexGPT и GigaChat (OAuth, обновление токена) на подменённом HTTP,
маскировка секретов, обработчики Telegram-бота.

## Ограничения

- Сканы PDF без текстового слоя не читаются (нужен OCR — можно добавить).
- В DOCX нет номеров страниц (их расставляет Word при вёрстке), поэтому
  ссылка ведёт на раздел.
- Поиск без эмбеддингов опирается на слова: перефразы без общих слов
  находятся хуже — для них включается гибридный поиск.
- Бот отвечает на каждый вопрос отдельно, без памяти диалога.
- Живые запросы к YandexGPT, GigaChat и OpenAI в этой поставке не делались
  (нет ключей) — форматы запросов сверены с документацией и проверены
  тестами на подменённом HTTP. Первый запуск с ключом — 5 минут проверки.
