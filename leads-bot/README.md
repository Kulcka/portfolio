# Бот для приёма заявок в Telegram и MAX

Клиент пишет боту в Telegram или в MAX, выбирает услугу, оставляет имя, телефон и
комментарий. Заявка сохраняется в базу, администратор сразу получает уведомление
в рабочий чат, а выгрузку в Excel можно получить одной командой.

## Что умеет

- **Сценарий заявки:** согласие на обработку персональных данных → услуга (список
  из настроек) → имя → телефон → комментарий (можно пропустить) → проверка и отправка.
  Можно отменить (`/cancel`) или заполнить заново.
- **Телефон:** кнопка «Отправить мой номер» или ввод вручную в любом привычном виде
  (`8 999 123-45-67`, `+7 (999) 1234567` …). Номер проверяется и сохраняется в едином
  виде `+79991234567`.
- **Уведомление администратору** в админ-чат: услуга, имя, телефон, комментарий,
  ссылка на профиль клиента в мессенджере, время. Можно скрывать номер в уведомлении.
- **Защита от спама:** не больше N заявок от одного человека за час (N — в настройках);
  бот говорит, через сколько минут можно отправить следующую.
- **Для администратора:** `/stats` — заявки за сегодня, за 7 дней и всего, по услугам
  и по каналам; `/export` — файл Excel с заявками прямо в чат.
- **Один бот — два мессенджера:** Telegram и MAX работают из одного процесса на общей
  базе. Можно включить только один.
- **Настройка без программиста:** услуги, все тексты, ссылка на политику — в
  `config.yaml`. Ошибку в настройках бот покажет при запуске и не запустится с ней.

## Как устроено

```
leads_bot/
  core/            ядро без привязки к мессенджеру
    service.py     сценарий заявки (шаги, согласие, антиспам)
    storage.py     SQLite: заявки, незаконченные анкеты
    phone.py       проверка и нормализация телефона
    notify.py      текст уведомления администратору
    stats.py       /stats
    export.py      /export — Excel
  transports/
    telegram.py    Telegram (aiogram 3)
    max_api.py     HTTP-клиент Bot API MAX
    max_bot.py     MAX: long polling или webhook
  app.py           запуск и присмотр за транспортами
  console.py       демо-режим в терминале
config.yaml        услуги, тексты, политика
.env.example       пример переменных окружения (секреты — в .env)
deploy/            systemd-юнит и пример nginx для webhook MAX
tests/             143 автотеста (pytest)
```

Если один мессенджер недоступен (сеть, сбой у площадки), второй продолжает работать.
Неверный токен — понятное сообщение в логе, без бесконечных перезапусков.

## Быстрый старт на Windows

Нужен Python 3.11 или новее.

```powershell
cd leads-bot
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
copy .env.example .env          # вписать токены — см. «Как получить токены»
notepad config.yaml             # название, телефон, услуги, ссылка на политику
.\.venv\Scripts\python -m leads_bot check-config
.\.venv\Scripts\python -m leads_bot run
```

Остановить — `Ctrl+C`. Попробовать сценарий без мессенджера и токенов:
`.\.venv\Scripts\python -m leads_bot console`.

## Запуск на Linux-сервере (systemd)

```bash
sudo useradd --system --home /opt/leads-bot --shell /usr/sbin/nologin leadsbot
sudo mkdir -p /opt/leads-bot && sudo cp -r . /opt/leads-bot && cd /opt/leads-bot
sudo python3 -m venv .venv && sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env && sudo nano .env && sudo nano config.yaml
sudo mkdir -p data && sudo chown -R leadsbot:leadsbot /opt/leads-bot && sudo chmod 600 .env
sudo -u leadsbot .venv/bin/python -m leads_bot check-config
sudo cp deploy/leads-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now leads-bot
journalctl -u leads-bot -f        # логи
```

Бот запускается вместе с сервером и перезапускается после сбоя. При ошибке настройки
(код выхода 78) systemd его не перезапускает — исправьте `.env`/`config.yaml` и
выполните `sudo systemctl restart leads-bot`.

## Docker

```bash
docker build -t leads-bot .
docker run -d --name leads-bot --restart unless-stopped --env-file .env -v leads-data:/app/data leads-bot
```

База лежит в томе `leads-data`. `Dockerfile` приложен как есть: в среде разработки
Docker не установлен, сборка образа не проверялась.

## Как получить токены

### Telegram

1. Откройте [@BotFather](https://t.me/BotFather), команда `/newbot`, задайте имя и
   адрес бота. BotFather пришлёт токен вида `123456789:AA…` — впишите его в
   `TELEGRAM_BOT_TOKEN`.
2. Создайте группу для заявок, добавьте в неё бота, отправьте в группе `/id` —
   бот ответит `chat_id`. Впишите его в `TELEGRAM_ADMIN_CHAT_ID` и перезапустите бота.
3. По желанию: `TELEGRAM_ADMIN_USER_IDS` — id сотрудников, которым `/stats` и
   `/export` доступны и в личке с ботом (свой id узнаётся той же командой `/id`).

### MAX

По документации MAX (<https://dev.max.ru/docs/chatbots/bots-create/create>, прочитано
27.09.2026):

> «Подключение к платформе MAX для партнёров и её сервисам — чат-ботам,
> мини-приложениям, каналам — доступно для юрлиц, ИП и самозанятых, которые являются
> резидентами РФ.»

> «Чтобы создать бота, вы сначала должны подключиться к платформе MAX для партнёров,
> создать и верифицировать профиль организации, ИП или самозанятого.»

Порядок:

1. Профиль организации/ИП/самозанятого на [business.max.ru](https://business.max.ru/self),
   верификация через Госуслуги или банковский ID (подробно —
   <https://dev.max.ru/docs/maxbusiness/connection>).
2. Раздел «Чат-боты» → «Создать», заполнить карточку. Бот проходит модерацию:
   «Проверка занимает до 48 часов по рабочим дням». Лимит: организация или ИП —
   5 ботов, самозанятый — 2.
3. После публикации на платформе появляется токен — впишите в `MAX_BOT_TOKEN`.
4. Добавьте бота в рабочий чат MAX, отправьте `/id`, впишите `chat_id` в
   `MAX_ADMIN_CHAT_ID`.

**Сертификат Минцифры.** API MAX (`platform-api2.max.ru`) работает с сертификатом,
выданным «Russian Trusted Sub CA» (Минцифры). Документация MAX: «добавить сертификат
Минцифры в список доверенных» (<https://dev.max.ru/docs-api/changelog-api>). Без этого
бот не подключится к MAX — в логе будет сообщение про сертификат. Два способа:

- Linux: положить корневой сертификат «Russian Trusted Root CA» (файл `.crt` в формате
  PEM) в `/usr/local/share/ca-certificates/` и выполнить `sudo update-ca-certificates`;
- или указать путь к файлу в `.env`: `MAX_CA_BUNDLE=/opt/leads-bot/certs/russian_trusted_root_ca.pem`.

Сертификат скачивайте только с официального сайта Госуслуг/Минцифры (раздел о
сертификатах НУЦ Минцифры).

**Long polling или webhook.** По умолчанию `MAX_MODE=polling` — удобно для проверки,
белый адрес не нужен. MAX рекомендует для боевой работы webhook: долгий опрос
«ограничено по скорости и сроку хранения событий — этот способ не подходит для
production-окружения». Для webhook нужен домен с HTTPS на порту 443 и сертификатом
доверенного центра (самоподписанные не принимаются): задайте `MAX_MODE=webhook`,
`MAX_WEBHOOK_URL=https://bot.example.ru/max/webhook`, `MAX_WEBHOOK_SECRET` и настройте
nginx по примеру `deploy/nginx-max-webhook.conf`. Бот сам оформит подписку при запуске
и будет проверять секрет в заголовке `X-Max-Bot-Api-Secret`. Оба способа одновременно
не работают.

## Где лежат данные

- Заявки — файл SQLite `data/leads.sqlite3` (путь меняется в `DATABASE_PATH`). Резервная
  копия — копирование этого файла (лучше при остановленном боте).
- Незаконченные анкеты хранятся не дольше `dialog_ttl_hours` (24 ч по умолчанию), потом
  удаляются автоматически.
- Если нужно хранить заявки ограниченный срок — `retention_days` в `config.yaml`
  (0 — хранить, пока не удалите сами).
- Логи — в консоль/journald; в логах нет имён, телефонов и токенов.

## Как выгрузить заявки

- В админ-чате Telegram или MAX: `/export` — бот пришлёт файл `leads_<дата>.xlsx`.
- На сервере: `python -m leads_bot export --out leads.xlsx`.
- Статистика: `/stats` в админ-чате или `python -m leads_bot stats`.

В файле два листа: «Заявки» (номер, дата и время по вашему часовому поясу, канал,
услуга, имя, телефон, комментарий, профиль, время согласия, версия политики, ушло ли
уведомление) и «Сводка» по услугам. Текст, похожий на формулу Excel (`=…`), сохраняется
как текст.

## Персональные данные (152-ФЗ): что сделано в боте

- **Согласие — отдельным шагом до сбора данных**, со ссылкой на политику обработки
  ПДн из `config.yaml`. Пока согласия нет, бот ничего не сохраняет — даже если человек
  сразу написал имя и телефон. При отказе данные не собираются, бот предлагает
  позвонить.
- **Факт согласия фиксируется** в каждой заявке: время, ссылка и версия политики.
- **Собирается минимум:** услуга, имя, телефон, комментарий; из мессенджера —
  id, username и имя профиля (чтобы ответить клиенту).
- **Отзыв согласия:** команда `/forget` удаляет все заявки и незаконченную анкету
  пользователя.
- **Сроки хранения:** брошенные анкеты удаляются через сутки; срок хранения заявок
  настраивается (`retention_days`).
- **Логи без персональных данных и без токенов.**
- **Уведомления без телефона** по желанию (`notifications.mask_phone: true`) — полный
  номер остаётся только в базе и выгрузке.

Что остаётся за владельцем бота: опубликованная политика обработки ПДн (у MAX есть
типовая: <https://dev.max.ru/docs/legal/privacy>), уведомление Роскомнадзора об обработке
ПДн, размещение сервера с базой в России, решение о том, допустимо ли пересылать данные
клиентов в админ-чат зарубежного мессенджера (Telegram). Точные требования уточните у
юриста — бот даёт технические инструменты, но не заменяет юридическую проверку.

## Настройка текстов

Все тексты — в `config.yaml`, разметка HTML (`<b>`, `<i>`, `<a href="…">`), общая для
Telegram и MAX. Подстановки в фигурных скобках:

| текст | подстановки |
|---|---|
| `consent` | `{company}`, `{policy_url}` |
| `consent_declined` | `{company}`, `{company_phone}` |
| `invalid_name` | `{min_length}`, `{max_length}` |
| `phone_saved` | `{phone}` |
| `comment_too_long` | `{max_length}` |
| `confirm` | `{service}`, `{name}`, `{phone}`, `{comment}` |
| `lead_accepted` | `{name}`, `{lead_id}` |
| `rate_limited` | `{count}`, `{minutes}`, `{company_phone}` |
| `idle_hint` | `{company}` |
| `data_deleted` | `{count}` |

В остальных текстах подстановок нет. Опечатку вида `{nmae}` бот найдёт при запуске.

## Команды

| команда | где | что делает |
|---|---|---|
| `/start` | личка с ботом | начать заявку |
| `/cancel` | личка | отменить заявку |
| `/forget` | личка | удалить свои данные |
| `/stats` | админ-чат | статистика |
| `/export` | админ-чат | Excel с заявками |
| `/id` | любой чат | показать id чата и пользователя (для настройки) |

```bash

```

## MAX: что проверено, а что нет

Адаптер написан по документации <https://dev.max.ru/docs-api> и OpenAPI-схеме
<https://github.com/max-messenger/api-schema> (прочитаны 27.09.2026). Живого бота MAX
в разработке не было: создание бота требует верифицированного профиля ИП, организации
или самозанятого.

Проверено на реальном сервере MAX (запросом без токена, 27.09.2026):
- адрес `https://platform-api2.max.ru` отвечает; без токена — `401
  {"code":"verify.token","message":"No access token"}`;
- сертификат сервера выдан «Russian Trusted Sub CA» и не проходит проверку ни в
  хранилище Windows, ни в стандартном наборе Python (certifi) — нужен корневой
  сертификат Минцифры.

Сделано по документации, на живом боте не проверено:
- формат событий `bot_started`, `message_created`, `message_callback` и ответ на
  нажатие через `POST /answers` (в том числе снятие кнопок: сообщение переписывается с
  пустым списком вложений);
- кнопка `request_contact` и разбор номера из vCard (`payload.vcf_info`);
- отправка файла выгрузки: `POST /uploads?type=file` → загрузка multipart → вложение
  `file` с токеном (в документации не до конца ясно, откуда брать токен — из первого
  ответа или из ответа сервера загрузки; клиент понимает оба варианта) и повтор при
  `attachment.not.ready`;
- приходят ли боту сообщения из группового чата MAX (нужно для `/stats` и `/export` в
  групповом админ-чате). Если нет — используйте `MAX_ADMIN_USER_IDS` и команды в личке.

Перед сдачей боевого бота на MAX эти пункты проверяются на тестовом боте заказчика
за 15–20 минут.
