# Парсер сайтов → Excel / Google Sheets, с отчётом об изменениях и запуском по расписанию

Собирает товары (или любые другие записи) с сайта по описанию в YAML-файле, выгружает в
**CSV, Excel и Google Sheets**, сравнивает с прошлым запуском — **что появилось, где изменилась
цена, что пропало** — и присылает сводку в **Telegram**. Запускается вручную или по расписанию
(Планировщик Windows, cron / systemd на Linux).

Под новый сайт код не переписывается: меняется только YAML-конфиг (селекторы, поля, пагинация).

Пример результата — в папке [`examples/`](examples/): живой прогон учебного каталога
[books.toscrape.com](https://books.toscrape.com) (40 книг с характеристиками и картинками) и
[quotes.toscrape.com](https://quotes.toscrape.com) (100 цитат).

## Что умеет

| Возможность | Как устроено |
|---|---|
| Каталог с пагинацией | ссылка «Дальше» или шаблон `?page={page}`; лимит страниц; защита от зацикливания; остановка на пустой странице или 404 |
| Карточки товаров | переход из списка в карточку, поля из обеих страниц сливаются в одну строку |
| Поля | CSS-селектор → текст / HTML / любой атрибут → регулярное выражение → словарь замен → тип |
| Типы | строка, целое, число, **цена** (`1 299,00 ₽`, `$1,299.99`, `1.299,99 €`), **валюта** (₽, $, €, £, ₸, коды ISO), **наличие** («В наличии», «Нет в наличии», «Под заказ», «In stock (22 available)»…), да/нет, ссылка (относительная → абсолютная) |
| Характеристики | таблица или список `dt/dd` любого состава → отдельные колонки (у разных товаров разные — соберутся все) |
| Картинки | скачивание в папку, имя файла = артикул, путь — в колонке таблицы; уже скачанные не качаются повторно |
| Выгрузка | CSV (UTF-8 с BOM, открывается в Excel без «кракозябр»), XLSX (шапка, автофильтр, ширина колонок, формат цен, кликабельные ссылки, листы «Изменения» и «Сводка»), JSON, Google Sheets |
| Изменения | история прогонов в SQLite; отчёт «новые / изменилась цена / пропали / другие поля»; защита от ложных «пропали» при сбое сайта |
| Уведомления | Telegram: сводка изменений или сообщение о сбое прогона |
| Бережность к сайту | пауза между запросами, свой User-Agent, соблюдение robots.txt (включая Crawl-delay), повторы с растущей паузой при ошибках 429/5xx, учёт `Retry-After` |
| Надёжность | ни одной записи — файлы и история не трогаются; файл открыт в Excel — результат сохраняется рядом; токены маскируются в логах |
| Отладка | команда `check` показывает первые записи и заполненность колонок; кэш страниц на диске |

## Быстрый старт

Нужен Python 3.10+ (проверено на 3.11, Windows 11).

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

# проверить селекторы: 1 страница, 3 записи, ничего не сохраняется
.\.venv\Scripts\python -m site_parser check configs\books_toscrape.yaml

# полный прогон (весь каталог — 50 страниц и 1000 карточек, ~20 минут)
.\.venv\Scripts\python -m site_parser run configs\books_toscrape.yaml

# короткий прогон: 2 страницы каталога, 10 картинок
.\.venv\Scripts\python -m site_parser run configs\books_toscrape.yaml --max-pages 2 --max-images 10
```

На Linux/macOS — `.venv/bin/python` вместо `.\.venv\Scripts\python`.

Результат: `output/<имя>/` — `books.csv`, `books.xlsx`, `books.json`, `changes.md` (отчёт об
изменениях; архив — в `reports/`), `images/`. Журнал — `logs/site_parser.log`.

### Команды и параметры

| Команда | Что делает |
|---|---|
| `run КОНФИГ` | полный прогон: сбор → картинки → сравнение → выгрузка → уведомление |
| `check КОНФИГ [--limit N]` | пробный сбор с первой страницы, вывод записей и заполненности колонок |
| `history КОНФИГ` | список прошлых прогонов |

Параметры `run`: `--max-pages N`, `--max-items N`, `--max-images N` (0 — не качать), `--cache` /
`--no-cache`, `--no-notify`, `--no-sheets`, `--notify-preview ФАЙЛ` (сохранить текст уведомления),
`--no-state` (не записывать в историю), `--note ТЕКСТ`, `--env-file ФАЙЛ`, `-v` (подробный лог).

Коды выхода: `0` — успешно, `1` — прогон не удался, `2` — ошибка конфига, `3` — готово с
предупреждениями (часть страниц не загрузилась, не обновилась Google-таблица, не ушло уведомление).

## Как описать новый сайт

Скопируйте [`configs/_template.yaml`](configs/_template.yaml) и замените селекторы. Селекторы
удобно подбирать в браузере: правый щелчок по цене → «Просмотреть код» → класс элемента.

```yaml
name: my_shop
title: Мой магазин
start_urls:
  - https://example.com/catalog/phones

request:
  delay: 1.5                      # пауза между запросами, секунд
  user_agent: "MyShopParser/1.0"

list:                             # страница категории
  item: div.product-card          # одна карточка = одна строка таблицы
  link: a.product-card__link      # ссылка на страницу товара
  fields:
    title: {css: .product-card__title, label: Название, required: true}
    price: {css: .price__current, type: price, label: Цена}
    in_stock: {css: .stock, type: availability, label: В наличии}

pagination:
  next: a.pagination__next        # или template: https://example.com/catalog?page={page}
  max_pages: 100

detail:                           # страница товара
  fields:
    sku: {css: '[itemprop="sku"]', label: Артикул}
    images: {css: .gallery img, attr: data-src, multiple: true, label: Картинки}
  specs: {rows: .specs tr, key: th, value: td}   # все характеристики — в колонки

images: {field: images, dir: images}

changes:
  key: sku                        # по чему узнавать товар между прогонами
  track: [in_stock]               # что отслеживать, кроме цены
```

Параметры поля:

| Ключ | Значение |
|---|---|
| `css` | CSS-селектор внутри карточки (или страницы товара). Доступны `:has()`, `:nth-of-type()`, `:-soup-contains("текст")` |
| `attr` | `text` (по умолчанию), `html`, `own_text` (без вложенных тегов) или имя атрибута: `href`, `src`, `data-src`, `content`, `class`… |
| `regex` | регулярное выражение; если в нём есть группа `( )` — берётся она |
| `map` | словарь замен: `{One: 1, Two: 2}`, `{"Мало": true}` |
| `type` | `str`, `int`, `float`, `price`, `currency`, `availability`, `bool`, `url` |
| `multiple` | `true` — все найденные элементы списком (в таблице через запятую) |
| `default`, `required`, `label` | значение по умолчанию; без поля запись пропускается; заголовок колонки |

Пример из рабочего конфига: рейтинг на books.toscrape.com задан классом `star-rating Three` —
`attr: class` + `regex: 'star-rating\s+(\w+)'` + `map: {One: 1, …, Five: 5}` + `type: int` дают
число 3. Все ключи — в [`configs/books_toscrape.yaml`](configs/books_toscrape.yaml) с комментариями.

Опечатки в конфиге не проходят молча: `list.fields.price.type: неизвестный тип 'prise'`,
`неизвестные ключи selecter`, неверный CSS-селектор или регулярка — ошибка сразу при запуске.

Другие режимы: список ссылок на карточки из файла (`start_urls_file: urls.txt`, без секции
`list`); несколько категорий — несколько `start_urls`; заголовки запроса (например, cookie
региона) — `request.headers`; прокси — стандартные переменные окружения `HTTPS_PROXY`.

## Google Sheets

Выгрузка идёт от имени **сервисного аккаунта** Google — отдельной «учётки для программ», пароль
от вашей почты не нужен. Настраивается один раз, ~10 минут:

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/), создайте проект
   (или выберите существующий).
2. «APIs & Services» → «Library» → включите **Google Sheets API** и **Google Drive API**.
3. «IAM & Admin» → «Service Accounts» → «Create service account». Роли выдавать не нужно.
4. Откройте созданный аккаунт → вкладка «Keys» → «Add key» → «Create new key» → **JSON**.
   Скачанный файл положите в проект как `secrets/service-account.json` (папка в git не попадает).
   Если создание ключа запрещено политикой организации, это настраивает администратор Google
   Workspace.
5. Скопируйте почту сервисного аккаунта (вида `имя@проект.iam.gserviceaccount.com`, есть в JSON в
   поле `client_email`). Откройте нужную Google-таблицу → «Настройки доступа» → добавьте эту почту
   с правом **«Редактор»**.
6. Скопируйте `.env.example` в `.env` и заполните:
   ```
   GOOGLE_SERVICE_ACCOUNT_FILE=secrets/service-account.json
   GOOGLE_SHEET_ID=1AbC...xyz          # часть адреса таблицы между /d/ и /edit, или вся ссылка
   ```
7. Запустите прогон. В таблице появятся листы «Товары» и «Изменения»; при каждом прогоне они
   перезаписываются целиком.

Если таблица не открыта для сервисного аккаунта, парсер так и напишет — с почтой, которую нужно
добавить. Без Google-настроек всё остальное (CSV, Excel, отчёт, Telegram) работает как обычно.

## Уведомления в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Напишите боту любое сообщение, затем узнайте свой `chat_id` (например, у @userinfobot) — или
   добавьте бота в группу.
3. В `.env`: `TELEGRAM_BOT_TOKEN=...`, `TELEGRAM_CHAT_ID=...`.

По умолчанию сообщение приходит, только когда есть изменения или ошибки
(`notify.telegram.only_changes`). При сбое прогона по расписанию приходит короткое сообщение о
причине. Токен нигде не печатается: ни в журнале, ни в текстах ошибок. Пример сообщения —
[`examples/books/telegram_message.txt`](examples/books/telegram_message.txt).

## Запуск по расписанию

### Windows (Планировщик заданий)

```powershell
# ежедневно в 09:00
.\scheduling\windows\register_task.ps1 -Config configs\books_toscrape.yaml -At 09:00

# каждые 4 часа начиная с 08:00
.\scheduling\windows\register_task.ps1 -Config configs\books_toscrape.yaml -At 08:00 -EveryHours 4

# посмотреть, что будет сделано, ничего не меняя / удалить задачу
.\scheduling\windows\register_task.ps1 -Config configs\books_toscrape.yaml -WhatIf
.\scheduling\windows\register_task.ps1 -Config configs\books_toscrape.yaml -Unregister
```

Скрипт проверяет конфиг до регистрации, задача запускается из папки проекта, пропущенный из-за
выключенного компьютера запуск выполняется при включении, два прогона одновременно не идут.
Права администратора не нужны (задача работает, пока пользователь вошёл в систему; для работы без
входа — ключ `-RunWithoutLogon`). Если PowerShell запрещает запуск скриптов:
`powershell -ExecutionPolicy Bypass -File .\scheduling\windows\register_task.ps1 ...`.
Результат последнего запуска (код выхода) виден в Планировщике.

### Linux (systemd или cron)

Готовые файлы — в `scheduling/linux/`: шаблонные юниты `site-parser@.service` и
`site-parser@.timer` (имя конфига подставляется после `@`) и `crontab.example`.

```bash
sudo cp scheduling/linux/site-parser@.* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now site-parser@books_toscrape.timer   # configs/books_toscrape.yaml
systemctl list-timers 'site-parser@*'
```

Время запуска меняется в `OnCalendar` таймера; пропущенный запуск догоняется (`Persistent=true`).

## Как читать отчёт об изменениях

Каждый прогон сохраняется в `state/site_parser.sqlite3`. Следующий прогон сравнивается с
последним **полным** (без ошибок загрузки) и делит изменения на:

- **новые** — записи, которых не было;
- **изменилась цена** — было/стало и процент, отсортировано по величине изменения;
- **пропали** — записи, которых больше нет;
- **другие изменения** — поля из `changes.track` (наличие, остаток, старая цена…).

Если прогон прошёл с ошибками или записей стало меньше половины от прошлого раза, раздел
«пропали» не заполняется: это почти всегда сбой сайта или сети, а не снятие всего ассортимента.

Отчёт дублируется в `changes.md`, на лист «Изменения» в Excel и Google Sheets и в Telegram.

## Законность и бережность

- Парсер собирает **только открытые данные** — то, что видит любой посетитель без входа в
  аккаунт. Обход авторизации, капчи и платного доступа не предусмотрен.
- **robots.txt соблюдается по умолчанию**, включая `Crawl-delay`. Если сайт закрыт для роботов
  или robots.txt недоступен из-за ошибки сервера, страницы не запрашиваются.
- **Нагрузка минимальная**: запросы идут по одному, с паузой (по умолчанию 1–1,5 с), при ошибках
  пауза растёт; User-Agent честно называет программу.
- **Персональные данные не собираются** (152-ФЗ «О персональных данных»): конфиги описывают
  товары, цены, характеристики — не ФИО, телефоны и почты людей. Сбор персональных данных без
  законного основания мы не берём в работу.
- Копирование **всей или существенной части** чужой базы данных может затрагивать права её
  изготовителя (ст. 1334 ГК РФ), а тексты и фото — авторские права. Для мониторинга цен и
  собственной аналитики это обычно не проблема; для публикации чужих данных у себя стоит
  проверить условия сайта.
- Перед запуском на новом сайте стоит прочитать его пользовательское соглашение.

Это не юридическая консультация, а принципы, которых придерживается проект.

## Ограничения и расширения

- **Сайты, которые рисуют каталог JavaScript-ом** (данные подгружаются после загрузки страницы).
  Часто достаточно найти в браузере (вкладка «Сеть») JSON-запрос, из которого сайт берёт данные,
  и собирать его напрямую — это быстрее и бережнее. Если нет — подключается режим браузера
  (Playwright): сетевой слой заменяется, конфиги и выгрузка остаются прежними. В базовую поставку
  не входит (браузеру нужно ~300 МБ).
- Сайты с капчей, обязательным входом или явным запретом в robots.txt — не парсим.
- Запросы идут последовательно: 1000 карточек при паузе 1 с — около 20 минут. Для бережности это
  сделано намеренно.

## Устройство проекта

```
site_parser/        код: config, fetcher (сеть, robots.txt, кэш), extract, converters, scraper,
                    images, storage (SQLite), diff, report, exporters, gsheets, notify, pipeline, cli
configs/            конфиги сайтов и шаблон _template.yaml
scheduling/         Планировщик Windows (register_task.ps1), systemd и cron для Linux
scripts/            simulate_changes.py — для демонстрации отчёта на статичном учебном сайте
examples/           результаты живых прогонов
tests/              тесты pytest на сохранённых страницах (без сети)
```

Разработка: `pip install -r requirements-dev.txt`, затем `python -m pytest` (160 тестов, без
выхода в сеть), `ruff check .`, `mypy`.
